LOCAL WORKSPACE

From your video to inspectable evidence.

Use your Mac to test the whole pipeline today. Model quality and recovered motion can vary; unsupported steps remain visible.

1. Start the app

Double-click Launch Workspace.command in the interaction-twin project folder. It opens the local project page and keeps the processor in a Terminal window. Choose Open workspace for the editor, or Try your video to start a new recording. Leave that Terminal open while processing videos.

If the app is already running, the launcher reuses it. It does not install models, access the cluster or publish your recordings.

2. Add a video

Click ＋ New video, choose an MP4, MOV or WebM, then name your project. Use an existing recording from your phone or another video source. Clear views help reconstruction, but a calibration recording or special capture setup is not required.

The original upload is stored on this computer. After you select the consent checkbox and press Run, the chosen profile sends sampled frames to Meta or OpenAI/Codex for reasoning. A SAM 3.1 video profile also sends an explicitly sampled video derivative to Meta. The consent label identifies the selected provider.

3. Choose a profile and run

Meta reasoning + local 3D uses Muse Spark reasoning with the local SAM 2.1 baseline. The SAM 3.1 API profiles additionally use hosted image segmentation or video propagation from automatic model boxes. Video quality and complete fresh runs require their own receipts. The preserved Local smoke and Local low profiles use OpenAI/Codex reasoning. Smoke samples coarsely; low uses 1 fps and usually takes longer. Profiles budget up to three eligible component observations. Model labels and overlap checks guide diversity, but selected tracklets can still repeat a real part. Neither guarantees an accurate mesh or a recovered hidden interaction.

Select the hosted-reasoning consent checkbox, then click Run pipeline →. Watch Pipeline runs for real phase progress, logs, errors and cancellation. Processing uses one model worker at a time.

The app checks input → discovery → SAM masks → audit → view selection → reconstruction → pose → tracking → reasoning → procedure → workspace. Reconstruction, pose and motion keep separate per-part receipts; successful components survive a sibling failure. A failed optional stage is recorded as a gap; no successful pose or interaction is fabricated.

4. Inspect and export

Choose Open result when the run finishes. Replay pairs the original-timing video with generated components. Orbit the scene, switch to the matching video camera, toggle components or inspect assets separately. Selected component motion shows only the chosen part in its own camera coordinates. Recorded positions needs an explicit shared gauge; independent generated units are never silently assembled.

Components & states shows candidate relationships and exact-sample states. Procedure links each step to its original frames. Export project provides the interaction JSON, readable procedure, replay checks and generated GLB assets.

A visible 3D model is an estimate. A missing model at an unsupported time is intentional. Overlap or disappearance does not prove insertion, contact or seating.

5. Review and correct the interpretation

Choose Review & correct, then select a procedure step, candidate relationship or point visual state. Evidence thumbnails seek the source recording while the review panel stays open beside Replay.

Accept, edit or reject the interpretation and choose Apply to draft. Existing participants, state values and source observations remain the reference vocabulary. Rejecting a point state makes it unknown; no state persists between observations. Acceptance does not verify physical identity, insertion or contact.

Save new revision validates evidence and writes a separate immutable human-review record. Original automatic restores the unchanged model output; saved history loads earlier reviews. Export project offers human-review JSON and a reviewed text guide alongside the original automatic exports. Offline drafts are explicitly unsaved: export them before closing or reloading.

6. Compare evidence and connect an agent

Open Benchmark → to inspect preserved cohorts, mask/asset counts, conditional motion coverage, actual linked runtimes and retained failures. These measurements do not establish physical accuracy or statement correctness. The first fresh multipart Jabra run produced three small-piece observations; it did not establish a case/lid/earbud assembly.

Open Agent catalog → to browse saved responses computed from validated local artifacts. This preview does not run an LLM or connect to MCP. It includes a local MCP client configuration; the complete setup is in docs/mcp.md.

The actual MCP stdio server is read-only: it can expose saved components, cited procedures, exact-time states, GLBs, source frames and a descriptive simulation handoff. It cannot start inference, upload media, change GPU jobs or execute robot actions. Simulation readiness remains false.

Upgrade a saved project

Open Model Lab → to choose a published project and component. Its source anchor, original generated mesh and evidence counts appear together. Refit the current mesh reuses geometry; Try a local reconstruction generates another TripoSR comparison. Both reuse exact saved reasoning instead of making hosted calls.

Choose Inspect plan before Start local upgrade. The plan shows reused evidence and the stages that will run. Results receive separate records; progress, cancellation, logs and failed attempts remain visible. Comparisons use exact common source timestamps with reference initializations excluded. A changed sampling rate is disclosed.

For future GPU use, choose SAM 3D Objects or SAM 3.1 · one-image mask comparison and Prepare input bundle. Download the ZIP and follow its README using your own prepared GPU runtime. This app submits no cluster job and downloads no model. Import the returned result ZIP beside the matching job. SAM 3D assets can continue through local alignment; SAM 3.1 results remain anchor-mask comparisons and do not inherit old SAM 2 audits or cross-frame identity.

See docs/model-upgrades.md and docs/model-handoffs.md for commands and limits. The shareable workflow diagram is on the local project page. Recordings and bundles remain private on this computer until you separately choose to share them.

Saved-view comparison

The Saved-view variant · diagnostic project reuses the same 14-step interpretation with a separately selected earbud reconstruction. Nine independent single-image candidates were generated and compared on declared source samples. This is not multi-view shape fusion.

The old base/lid remain selected. The earbud variant has 14/24 validation supports versus 12/24; both reach 15/15 on final-test frames, where the variant has weaker fit measurements. Its 40 conditional non-reference poses versus 38 still end at the same point. The original project remains the default; no hidden insertion or improved physical accuracy is established.

Open all nine candidates and comparison receipts → (requires the local processor). The versioned benchmark includes this variant as a separate cohort.

7. Take a portable interaction asset

Choose Export project → Create portable package. The processor verifies the published original and bundles its generated GLBs, source evidence, masks and descriptive interaction program into a ZIP with an offline viewer. Full source video is optional and off by default. This operation runs no model or paid API.

Extract the ZIP and open index.html. The viewer works without the project folder or an internet connection. Inspect each generated asset, the cited source frames and exact-time state observations. Independently scaled objects stay separate; unknown motion stays absent. Human-review revisions remain separate exports.

Use scripts/inspect_twin_package.py to verify or safely import an archive. A separate scripts/demo_twin_agent.py example retrieves a saved twin through the actual local MCP server, validates its asset hashes and creates a portable package. That client is scripted and uses no LLM; it does not execute a robot or establish simulation readiness. See docs/portable-assets.md and docs/scripted-agent.md.

8. Follow model quality and estimated usage

Meta reasoning and hosted SAM 3.1 image and video requests now work through the official API. Keep prior local results as comparison baselines. SAM 3D Objects remains a separate CUDA reconstruction task requiring a prepared GPU runtime and approved weights; an API key alone does not provide that 3D model.

Meta requests share a $100 local estimated-cost allowance. The app records used and reserved estimates and stops its own requests at the guard. This is not an account-wide billing cap or a verified credit balance; check Meta’s dashboard for actual charges and credits. Credentials stay in the private, ignored key file and never enter exported projects. See docs/pipeline.md for profiles and docs/upgrade-models.md for the separate GPU checklist.

9. Understand a task and improve the next recording

Open Understand. Saved Meta task analyses explain the interaction with cited frames, candidate relationships, visual checks, gaps and a capture checklist. Click any timestamp to return to the actual source. These are model interpretations; identifier validation does not establish semantic correctness.

Choose Analyze with Meta for one bounded request, or write a question and choose Ask Meta. Identical completed requests reuse their saved results. Saved questions stay selectable in the history. No model runs simply because you open the page. Failed requests and unsupported proposal items stay recorded; a recovery can omit invalid items without changing their cited evidence.

The evidence browser filters by component and mask-review status. In Replay, Component masks pauses at an exact saved frame and shows that program’s own masks. The separate Hand masks control is a saved hand-occlusion baseline where available.

10. Author a robot rehearsal

Open Robot Task Studio →. Choose a real generated asset, edit the source and target anchors, and preview taking a part out or putting it back. Source video and authored robot time remain independent. The arm, presentation scale, grasp attachment and motion are illustrative.

Export a JSON task draft to keep your anchors, selected asset hashes and evidence citations. It is deliberately non-runnable: no physics engine, robot controller, collision checking or verified contact is included. Read the simulator integration plan → for the MuJoCo first experiment and later Isaac Sim/Lab path. The MCP manifest includes the deterministic readiness report and missing physical fields.

11. Work with the footage you already have

Upload an existing video →. The main workflow accepts ordinary recordings. Automatic discovery, SAM masks, source-pixel or learned correspondences, per-part reconstruction and image checks produce the evidence supported by that clip. No checkerboard is required.

Camera parameters and object shape are estimates. Reconstruction Studio now compares saved camera hypotheses and can estimate a camera from up to three training frames with the prepared local MoGe-2 model. Choose “Estimate from video · experimental” when rebuilding a component, or the experimental camera processing profile for a new upload. Geometry is rebuilt with that estimate; old geometry keeps its original camera. The first matched tests establish no accuracy improvement, so the original camera mode remains the default. A moving lid or earbud is processed separately from the rest of the object. Occluded intervals, unseen surfaces and unresolved common scale remain explicit.

Inspect the actual local camera-estimation pilot → and its matched original-method control →. Both recover 443 sparse points and pass two of seven reserved views. This is working integration, not a complete scan or physical validation. A video can produce useful visual assets and descriptive interaction programs while exact dimensions, hidden geometry or physical contact remain unknown. Those unknowns do not block importing and analysing an ordinary video. Inspect reconstruction evidence → or review the separate physical-validation requirements →.

Offline review

Opening workspace/index.html directly lets you inspect saved projects without the processor. You can also prepare and export an explicitly unsaved human-review draft. To save an immutable revision, upload or run a new video, start the launcher and use the localhost page.
